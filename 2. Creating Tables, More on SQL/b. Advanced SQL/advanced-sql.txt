Self Joins 

There are cases where you may want to join a table to itself,
eg. to find pairs of entries which have something in common.

Example 

create table residences (
    id integer 
        references students,
    building text 
        references buildings (name)
    room text
)

We'd have a table that looks like this:

+--------+----------+------+
|     id | building | room |
+========+==========+======+
| 413001 |   Crosby |   10 |
| 496747 |   Crosby |   19 |
| 612413 |   Crosby |   31 |
| 170267 | Dolliver |    1 |
| 104131 | Dolliver |   14 |
| 477801 | Dolliver |    8 |
| 118199 | Kendrick |   1A |
| 105540 | Kendrick |   3B |
+--------+----------+------+

Say we wanted to find who is roommates (have the same building and room number).

We could accomplish this with a self join.

We could use this query:

select a.id, b.id, a.building, a.room
    from residences as a, residences as b
 where a.building = b.building
   and a.room = b.room
   and a.id != b.id
group by a.room
order by a.building, a.room;

To achieve the following result:

+--------+--------+----------+------+
|     id |     id | building | room |
+========+========+==========+======+
| 881256 | 413001 |   Crosby |   10 |
| 741532 | 496747 |   Crosby |   19 |
| 931027 | 612413 |   Crosby |   31 |
| 958827 | 170267 | Dolliver |    1 |
| 707536 | 104131 | Dolliver |   14 |
| 505241 | 477801 | Dolliver |    8 |
| 824292 | 118199 | Kendrick |   1A |
| 231742 | 105540 | Kendrick |   3B |
+--------+--------+----------+------+


Counting the Results of a Join

Counting rows in a single table is trivial. A column aggregeted with the count 
function will return the number of rows in the table, or the number of rows for each
value of a group by clause.

Examples:


select count(*) from animals;

- returns the number of animals in the zoo


select count(*) from animals where species = 'gorilla';

- returns the number of gorillas


select species, count(*) from animals group by species;

- returns each species' name and the number of animals of that species 


Things get complicated of we want to count the results of a join. 

For example, say we have two tables.


Products

SKU     PRICE       NAME 
101     $4.13       Ash Diffuser
222     $11.11      Circular Fluid
343     $61.20      Auxillary Vise
1025    $0.33       Coaxial Grommet

Sales

SKU     SALE DATE   COUNT
222     2009-04-13  4
343     2010-05-31  1
222     2011-11-11  4

Suppose that we want to know how many times we have sold each product.
In other words, for each sku value in the products table,
we want to know the number of times it occurs in the sales table.
We might start out with a query like this:

select products.name, products.sku, count(*) as num 
    from products join sales 
        on products.sku = sales.sku 
    group by products.sku;

But this query might not do exactly what we want.
If a particular sku has never been sold — if there are no entries for it in the sales
table — then this query will not return a row for it at all.

If we wanted a result of all products, including ones with no sales (0 count),
we can use this query:

select products.name, products.sku, count(sales.sku) as num 
    from products left join sales 
        on products.sku = sales.sku 
    group by products.sku;

Using count(sales.sku) will only count rows where sales.sku is defined.
This is important because we want to get a count for how many of each product
in the product table was sold - if we count * or products.sku for example,
we would get a '1' as the count since the sku exists in the products table!
We only want to count the sales.

Left (outer) joins are an alternative to the default inner join.

Left (outer) and right (outer) joins mean that you join on either the left or right table.

So in the case of left joins, all rows of the left table will be included, 
even if they don't exist in the right table.

Inner joins only return rows that exist in both tables. 

Right joins are the same as left joins, but for the right table.


Subqueries / Subselects

So far, we've used 'select' on tables and joins of tables. 

But, we can also use 'select' on the result table of a 'select' query, 
using subqueries!

This is because the result of a table query (select) is always another table.

This can be accomplished by using '()' to nest queries.


Example 

select avg(bigscore) from 
    (select max(score) as bigscore
        from mooseball
    group by team)
as maxes;


Notice that the subquery result has a name - 'maxes'. SQL requires that we name 
subquery results, even though it's not used in the query.


See the Python Example - 2 queries.

This can be done in one query - see Python Example - 1 query!


Views

Every select query returns a table. So, we can have the database remember a select 
query for us, and make it available to later queries.

When we do this, it's called a view.


View Syntax

create view <viewname> as select...


View Example 

create view course_size as 
    select course_id,
        count(*) as num 
    from enrollment 
group by course_id;


Views are very useful if the same query will be used many times.
That way, we can just use the view instead of an entire subquery. 
It's like a shorthand version of a subquery, like putting commonly used 
code inside of a function.

Another use for a View is to only display some columns from a table that has a 
lot of columns. For example, you may have a table with 20 columns, and a lot 
of queries that only refer to 4 of them. So, you'd make a view with the 4 
columns of interest. This would make the code a lot more clear.

We can keep views in memory using Materialized Views.


Updating and Deleting Rows in a View 

In some cases, updating a view definitely does not make sense, like if a view of an aggregation.

It does in other cases, like a view that just presents a subset of the columns in a table.

** Modifying a view will also modify the underlying table it's based on!

So, updating and deleting view rows is supported in PostgreSQL. It isn't supported in 
SQLlite.
